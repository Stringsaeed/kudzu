## Additional S34 event-boundary requirement

`ports::EventStamp` is an opaque `u64` with `from_cg_event_timestamp` and `cg_event_timestamp`. It has no wall-clock/default conversion. The complete path is:

- S57 captures `CGEventGetTimestamp` from the CGEvent belonging to **`NSApp.currentEvent`**, in the handler that submits or changes key status.
- `FormService::submit(token, values, at)` forwards `at` unchanged through its admission worker to `FormChannel::submit_form(token, values, at)`.
- `FormService::panel_focused(token, focused, after)` forwards `Option<EventStamp>` synchronously to the port.
- S35 converts the opaque value to `kudzu_engine::EventStamp(raw)`. `Some(after)` maps to `form_panel_focused_after`; `None` maps to the conservative `form_panel_focused` fallback. Never replace missing event information with wall time, a worker timestamp, floating-point `NSEvent.timestamp`, or a fabricated zero.

`submission_and_focus_forward_the_original_cg_event_boundaries` pins both Some/None focus reports and a submit timestamp near `u64::MAX`, including values above floating-point integer precision. The new native signatures and immediate native submission-boundary marking were read after rebase. Native click hit-testing is now window-server based; the service fake records event stamps and models resolved interruption, not the native hit-test protocol.

## API and integration hand-off

- `ExpansionEngine::insert(...) -> Result<(), AdmissionError>`; `FormChannel::submit_form(FormToken, values, EventStamp) -> Result<(), AdmissionError>`. Runtime pause, exclusion, permission, interruption and paste failures are **not** admission errors.
- `ExpansionService::insert` and `QuickSearchSession::insert` return Tasks of admission results; callers must not display insertion success from them. `FormService::submit` returns `Result<Option<Task<Submission>>, SubmitStartError>`, with `Submission.admission`, memory acceptance revision and memory queue error. Disk durability still comes from `saved()`.
- `ExpansionService::outcomes()` and `FormService::outcomes()` return the same `Watch<Option<OutcomeNotice>>`. Only sequence, snippet ID, source and typed codes are exposed—no trigger, body, selection, form values or app names. Every notification gets a new sequence, including repeated identical outcomes. Health stays in the status Watch. S56/S57 subscribe/read their baseline **before** issuing an operation, then filter new notices by source/snippet; these are notifications, not synchronous per-task results.
- S40 routes `EngineEvents::activity` to **both** `expansion.activity_outcome(&event)` and `activity.record(event)`. D17 goes through `expansion.trigger_lost` and then this same Activity route once. `EngineEvents::expanded` still goes only to `library.record_expansion`; the engine's corresponding Expanded Activity report drives the outcome Watch, avoiding double usage counting.
- One shared `EngineInstances` allocator lives for the composition/router lifetime. Stop/retire the old Engine before `next_engine()` for a new Engine. The forwarding host retains that `EngineInstance`, qualifies native tokens with `form_token`, and fences retired host callbacks using `is_current`. Re-starting the same Engine keeps its namespace. Before submit/cancel/focus, S35 calls the current instance's `native_token`; a mismatch is StaleToken for submit and a no-op for cancel/focus. Never pass a retired token's raw sequence to the new Engine.
- After **every** start, S40 calls `expansion.resync()` and waits for its returned generation before admitting user insertion. Stop the feed only at service shutdown, not for ordinary engine restarts.
- `SubmissionWorker` is a narrow worker-start seam with a default Task-thread implementation. On Err it must drop the operation without retaining/running it. S40/S57 must retain/settle `SubmitStartError.restoration` just as they do explicit-cancel Tasks and handle either its spawn failure or target-activation failure.
- S35 implements `Pasteboard::read_text` using a text-only native read. Clipboard history's existing full snapshot API remains unchanged.

Integration edits outside the three service trees: engine/pasteboard port contracts and their fakes, new `ports/form_tokens.rs` plus its export, and existing fixture contract-test call sites. Earlier S27 reports receive a pointer to this current contract. No engine/core implementation changes were needed.
