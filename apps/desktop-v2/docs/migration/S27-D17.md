## New API and routing

- `ports::TriggerLost { snippet_id, trigger }` and required `EngineEvents::trigger_lost(TriggerLost)`. The report carries the **stored** trigger, never the typed casing/context or snippet output. It deliberately has no `Debug` or serialization implementation. `FakeEngine::emit_trigger_lost` forwards outside locks; `FakeEngineEvents::lost_triggers` collects reports for fixture tests.
- `ExpansionService::trigger_lost(TriggerLost) -> ActivityEvent` publishes a content-free notice and returns a content-free, `#[must_use]` event for the existing S40 router to pass to `ActivityService::record`. This keeps expansion independent of the Activity service. The routing test's `EngineEvents` implementation performs both calls.
- `lost_trigger_notice() -> Watch<Option<LostTriggerNotice>>`. `LostTriggerNotice` contains only an opaque `RecoveryId` and snippet ID. `message()` returns **“The trigger was removed; the snippet couldn't be inserted.”** and `action_label()` returns **“Retype trigger”**. Wakers run after the service lock is released. The latest loss replaces the previous notice and private payload; old IDs cannot consume a replacement.
- `take_trigger_for_retyping(RecoveryId) -> Option<RetypeTrigger>` consumes the notice/payload once. `RetypeTrigger::trigger()` gives the local product UI the original stored trigger only after an explicit action. It survives snippet edits/deletion and has no `Debug`/serialization. `dismiss_lost_trigger(RecoveryId) -> bool` forgets the payload without exposing it. Neither action writes the clipboard, records usage or calls snippet insertion.
- `ActivityOutcome::TriggerLost` is a fieldless failure outcome, with a “Trigger removed” label and fixed explanation shared with the notice through `TRIGGER_LOST_MESSAGE`. The service-created event has snippet ID/time but no trigger, app, or guessed typed/form origin. Activity also explicitly strips trigger text from any incoming `TriggerLost` outcome, even if it exactly matches a stored library trigger. The Activity ring remains memory-only and unavailable to logging, persistence, sync or agents.

S35 must map the native report's two fields into the port without logging the native `Debug` payload. S40's router forwards to expansion and records its returned event exactly once. Keep the native engine's separate insertion-failure Activity event: the new entry describes lost-trigger recovery, not a successful expansion. S56/S57 subscribe before reading the notice, render fixed wording, and pass its ID back for action/dismissal. Do not serialize the notice's private recovery state or expose it to agent tools.

**Retype is a local UI recovery action, not synthetic typing.** D17 does not supply a target-app identity and the native API has no raw trigger-retyping operation. After the user chooses the action, the UI can show the stored trigger for manual retyping in the intended app (or advise Undo there). It must not guess a target, rerun snippet insertion, or replace the clipboard the engine restored. Actual notice rendering remains S56/S57; native recovery remains S34/S35/S71.

## Checked against the restructured engine

Read `kudzu-engine/src/lib.rs`, `macos/engine/{mod,session,form_flow,replace}.rs` and `activity.rs` at the new base. No engine implementation was changed.

| Port/behavior | Native mapping and contract |
|---|---|
| Status/app/rect/permission/tap types | Already use the same `kudzu_core::system` types; no serde conversion or UI vocabulary is needed. The engine is macOS-only; app services/fakes remain OS-independent. |
| `start(events)` | A forwarding host bridges `Engine::new(host)` to the later event-sink installation. Start success is not proof of readiness; status reports listener state. |
| `reload` | Builds the index on its caller's thread, so the existing feed worker remains necessary. |
| `set_suppressed` | Synchronously sets the flag **and resets the matcher**. Corrected S27's “flag-only” wording. It performs no OS I/O or host callback; suppression does not disable form interruption. |
| `insert` | `insert_snippet_with_selection`; native enqueues and returns `()`. A port `Ok` means admission, not completed insertion. Final outcomes come through host callbacks. |
| `submit_form` | Also enqueues and returns `()`. Updated the port and `Submission.insertion` comments so callers do not treat `Ok` as proof of insertion. The worker performs token/interruption/target checks; `expanded` alone increments usage. |
| `FormRequest.target` / `Expansion` | Map native `target_app` / `ExpansionEvent` directly; field meanings are unchanged. |
| `panel_focused` | `form_panel_focused`, from main-thread key-status notifications before the next event. Clicks are settled by the next focus report; the simple service fake represents already-settled input, not that native protocol. |
| `trigger_lost` | Forward D17 in addition to existing Activity callbacks. No clipboard operation, source inference or target lookup in the app callback. |
